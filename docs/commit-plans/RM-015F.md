## Language understanding and authority

Keep existing explicit request resolution as an application compiler. A pure conversational layer recognizes common design requests/paraphrases (less cramped/easier circulation, better work area/daylight, cohesive/cozy/bright/serene palettes), selected-piece references and bounded recent **user** requests for finish/side/window follow-ups. It never treats assistant prose as permission. Current explicit targets win; ambiguous/missing/multiple references ask one grounded question. New requests do not inherit additions/removals/replacements/unlocks from history. Negated/contradictory requests remain conservative; supported named layout exclusions restrict target scope and fixed IDs rather than granting more authority.

The real provider is no longer behind the narrow explicit-keyword gate for all unknown language. Unknown safe requests use one strict structured design-intent interpretation call within the existing admission/deadline/serial budget. Its closed goal/target/category/finish/palette enums have no coordinates, dimensions, permissions, actions or arbitrary prose. The application turns a valid intent into a concrete, bounded clarification option naming the pieces/goal; it cannot prepare room edits on that interpretation alone. A visitor choosing that option creates an explicit fresh request, compiled independently by frontend/backend before preparation and Apply. This confirmation is useful only when language could not be resolved safely; common supported design requests go directly to the normal preview. Invalid/refused/unknown output preserves the room. No model output grants action scope.

Optional bounded clarification options are added compatibly to assistant replies, with app-authored request/label/selection/current room revision. The UI shows them in the conversation; controller selection checks their current message/room revision before sending a new normal request. Old options cannot edit a changed room. No generic new modal or setting. Recent context stays within existing40-turn/64KiB bounds and is computed before resolution identically on both ends.
