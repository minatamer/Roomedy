# Exact release inputs and evidence

18 October2026. [RM-014](../tickets/RM-014-prepare-linux-images-and-release-runbooks.md). [Allocation](../commit-plans/RM-014.md). [Tool identities](../../scripts/release/identities.json).

`pnpm release:inventory --out <file>` records a sanitized exact byte manifest, including relevant uncommitted/untracked files. It is **input inventory**, never Linux runtime proof. Root lockfile/manifests/configuration, app/package sources and prepared public assets, release/probe/installer scripts and pinned CI workflow participate. Generated outputs, node_modules, .env/private data, docs/source archives and test recordings do not. Blank committed `.env.example` templates do participate; they are excluded from images. Tests are separately exercised by the settled gate; they are not runtime image input.

The existing `.gitattributes` enforces LF text and raw binary assets (including the exact Kenney licence). Inventory hashes actual on-disk bytes with SHA-256, checks LF text and rejects source symlinks. It does not normalize a fingerprint to accept a mismatched checkout. Owned modified ignore/env/Docker text files were formatted to actual LF. Generated `next-env.d.ts`, `.next*`, dist and caches are outputs, not inputs. Each entry is a sorted relative path, byte count and raw byte digest; the input digest hashes those entries. A one-byte relevant edit, new untracked source or changed binary invalidates the digest. Bounds: ≤5000files/64MiB per file/256MiB aggregate. Paths/byte counts/hashes reveal no file contents or credentials; private environment files never enter this manifest.

Optional retained public chunks/workers/assets participate as `retained/<relative path>` with their actual bytes. Their location on the operator's disk is not identity. A retained-manifest timestamp is provenance for age checks, not a runtime input; its files are independently rehashed. No retained manifest is copied into a runtime image. Current+old public files may share a path only with identical bytes. Rename/version a materially changed public asset before rolling forward. Never overwrite an old catalogue/model/font path with different bytes and claim compatible retention.

`pnpm release:verify --proof <proof.json> --frontend <local ref> --backend <local ref> [--retained <verified context>]` requires current inventory, a **linux-runtime** record and fresh real Docker image inspection. The input digest, exact image IDs/labels, platform, user, tool identities and complete selected probes must match. Missing Docker/image observations, Windows-only records, input-only inventory, stale bytes/images/tools or incomplete probes reject. Controlled matching/stale unit fixtures verify this rule without inventing an actual Linux run. Proof is a local execution record, not a cryptographic third-party attestation or substitute for owner/security review.

`pnpm release:build` is a metadata-only dry run. `pnpm release:build --execute [--previous <snapshot>]` is the separate local build/probe action: frozen install, shared-first builds, non-root images, internal test network, bounded no-key probes, exact proof and a public-only compatible-asset snapshot under ignored `.release/run-*`. It never pushes, deploys or invokes a live provider. The Docker Linux engine is currently unavailable, so execution fails before building and actual Linux proof remains absent. Empty validated static/public directories are supplied as the frontend's named `previous-assets` build context on the first build. Do not build the frontend Dockerfile with an unspecified named context.

The private probe network has no external route; backend fake=true/paid=false/live-policy=false. Backend ports are unexposed; only a freshly allocated127.0.0.1frontend port is published. Probes check actual non-root Node/runtime imports, private/source-file exclusion, content-free health, fake readiness/config, fixed bridge, anonymous private POST denial, every actual public asset/chunk/worker byte via HTTP, and bounded shutdown/exit. Native browser execution remains separate from asset reachability. The helper removes only its created container/network identities. No unrelated service, image, volume or Docker state is pruned. Partial failure emits no passing proof.
