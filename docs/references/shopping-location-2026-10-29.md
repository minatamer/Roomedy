# Optional shopping location — source and limits

29 October 2026. RM-037 resolves a browser-provided coordinate to an approximate shopping country locally. It does not contact a reverse-geocoding service. The actual browser permission UI and physical device accuracy remain owner-only acceptance; tests use public city coordinates and synthetic denied/timeout/pending responses.

[MDN getCurrentPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition) documents secure-context/browser permission requirements, timeout, maximumAge and enableHighAccuracy. Calling the API from Enable location lets the browser own its permission prompt; previously granted/denied permissions can change whether a new prompt appears. `127.0.0.1` is a local trustworthy context; hosted use requires HTTPS. The application never bypasses browser/OS permissions or automatically reloads after permission changes. It supplies site-control/reload help after denial and retains Continue without location.

[Natural Earth terms](https://www.naturalearthdata.com/about/terms-of-use/) state that vector data is public domain. [Pinned original country GeoJSON](https://raw.githubusercontent.com/nvkelso/natural-earth-vector/9380cca83db5f9aef52d5e762765100745f84b27/geojson/ne_110m_admin_0_countries.geojson) is the deliberate source; SHA-256 `6866c877d39cba9c357620878839b336d569f8c662d3cfab4cb1dbe2d39c977f`. Derived `apps/frontend/public/data/shopping-countries-v1.json` has 175 country records, 319744 bytes, SHA-256 `79f447852b9ada658dd8b5bc41a71498c253fe7b0429f3f22d789d9316d52bb9`. Derivation: retain valid two-letter ISO_A2_EH (or ISO_A2) values, normalize Polygon to MultiPolygon arrays, preserve outer/hole rings, round longitude/latitude to three decimal places, strip all unrelated metadata, format the JSON. No owner data is involved. Changed outline bytes must use a new versioned URL to preserve cache identity.

[Dataset policy](https://www.naturalearthdata.com/about/) describes de facto boundaries. The 1:110m country outline is intentionally coarse and incomplete for some islands/coasts/borders; it is a shopping hint, not political, residence, service, legal or delivery verification. Ocean/unresolved/ambiguous, invalid or excessively uncertain positions do not become an invented country. Country lookup may be corrected in chat. No map or geopolitical claim is displayed.

The asset is requested from Roomedy only after the browser supplies a permitted position. The first-party asset URL contains no coordinate, query or body; credentials are omitted, redirects rejected, reads bounded to 1 MiB/30,000 vertices and network deadline 10s. No startup preload or remote geocoder request exists. A single low-accuracy browser request uses 12s positioning timeout and a five-minute maximum cached position age. Permissions may remain pending until the user answers; Continue without location cancels the application's owner and ignores any later browser callback. No watchPosition or retry loop exists. Only coarse country/locality plus a transient consent decision is published; coordinates never enter state, persistence, AI context or application logs.

[Frankfurter documentation](https://frankfurter.dev/) is the existing latest-reference source. This task changes no exchange implementation: fixed public EGP/EUR/GBP/AED/SAR→USD pair requests share no room, location or text; successful reference observations cache 15 minutes, future/invalid/>7-day values reject, and deterministic minor-unit conversion retains native amounts, rate/date/source/observation. Reference values may lag trading/checkout rates, particularly weekends; unsupported/missing rates leave a lead unpriced. Focused offline rate/conversion checks are distinct from a new live rate/provider-quality check.
