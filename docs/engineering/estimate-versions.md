# Estimate versions and format2 recovery — RM-028

Approve & save planning estimate captures a detached, deeply frozen consumer-planning record. It includes an opaque ID, bounded name/time, semantic room with original measurement evidence/revision, strict pricing inputs and source observations, calculated quantity/pack/can/tax/allowance/unknown lines and totals, and catalogue/rules/calculation/representation versions. Approval means the visitor reviewed a planning record; no supplier price/stock/order, contractor signature or issuer authentication follows. Incomplete costs and authored samples stay explicitly qualified.

Up to four versions fit inside the existing one-MiB UTF-8 project/recovery envelope. Current+Before retains its independent512-KiB semantic limit. Format2 reserves1024bytes for bounded recovery metadata; JSON download uses compact valid JSON so a saved project does not fail solely because of indentation overhead. Reaching a bound leaves useful current work and existing versions unchanged, with download/separate-project guidance. There is no silent pruning or permanent library.

## Draft, saved inspection and comparison

Later edits, manual price changes, explicit research refresh, Apply and Undo affect only the current draft. Saved record inputs/results never share mutable references with it. The same single cutaway can inspect a clearly labelled saved design and its exact itemized estimate. Draft chat/sourcing/scope writes and Undo are hidden or disabled during saved inspection; Return to current draft restores normal editing. Selection is presentation and never changes the accepted room, approved records, prices or expiry.

Compare a saved version with the current draft without checking out either. Show both known totals/currencies and unresolved counts, a same-currency difference only, relevant input/design/evidence change reasons, and full removed/added financial lines. No exchange conversion or incomplete-cost budget success is inferred. Detailed old sources and quantity calculations remain available by viewing that exact saved version.

An explicit two-step New draft from this version replaces the current draft, clears Undo and creates fresh operational identity/history. The confirmation explains replacement and recommends saving the current draft first. All approved versions, original Before and the original creation/expiry stay unchanged. This is a deliberate new draft, not an Undo action. Subsequent design/price/combined edits keep the shared RM-027 Undo behavior. The whole Plan & cost presentation is keyed by workspace identity, matching existing Project/cutaway ownership, so source cards, selected records and transient chat inputs cannot survive a numeric-revision restart.

## Closed project format and migration

Format2 contains the prior explicit format/version/catalogue/rules/current/baseline fields plus nullable accepted cost inputs and bounded saved versions. Version1 is explicitly migrated to format2 with no prices or approvals inferred. Future formats/rules/calculation/representation versions reject with an unavailable-version message rather than being repriced by a different engine. Unknown assets/invalid room values, inconsistent room/version IDs, duplicate snapshot IDs, changed computed totals, invalid pricing/units/currency, extra operational fields and oversized UTF-8 reject before replacing useful work. Exact saved calculations are checked with the declared supported pure engine; accepted historical observations/results are then retained unchanged. This consistency check is not a cryptographic signature: imported labels, approval and evidence are locally editable visitor-supplied claims.

The file projects accepted semantic fields explicitly. Raw photos/private filenames, chat, Undo, receipts, proposals, active operations/grants/tokens, runtime flags and resource URLs never enter it. Bundled supported catalogue and representation versions plus saved semantic appearance/geometry reproduce supported views; no merchant images or arbitrary asset URLs are loaded. Unsupported future representation changes require a matching Roomedy rather than a claimed pixel-identical historical render.

Downloaded files remain outside guest cleanup; there is no secure-erasure, tamper-proof, permanent-library or general accessibility claim.
