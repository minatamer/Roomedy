# Roomedy evaluation kit

18 October 2026. [RM-013](../tickets/RM-013-evaluate-ai-and-integrated-product-behavior.md). This kit distinguishes contract/integration safety, synthetic interpretation, natural-photo quality and hosted readiness. Only the first has deterministic passing evidence. No paid run, model download, GPU runtime or deployment has occurred.

## Run locally

Use the pinned workspace tools and lockfile. `pnpm evaluate` builds shared contracts and runs the offline kit. `pnpm evaluate --dry-run` lists safe planned metadata. With pnpm 11, pass options directly after the script name. `pnpm exec tsx scripts/evaluate-roomedy.mjs --cases repeated-b,assistant-a --max-cases 2` runs a subset after shared build. Neither command loads app-local environment files. Offline bootstrap forces fake/paid-off, removes inherited provider credentials and denies external fetch/HTTP/socket transports before application imports; deterministic tests use the same bootstrap and independently fixed child environment.

`node scripts/prepare-evaluation-corpus.mjs` deterministically rebuilds the eleven original vector scenes using the backend's existing pinned Sharp. It replaces only manifest-listed JPEGs and their byte hashes; it does not derive the hand-authored expected counts from output. Review an intentional fixture/truth change separately. There is no recursive dataset discovery or remote asset download.

## Live execution remains separately blocked

The example [policy](live-policy.example.json) deliberately fails validation. Before a later authorized run, fill a private, uncommitted policy with the exact case allow-list/count, model, dispatch/reserved-token/whole-run time ceilings, reviewed model-specific per-image token bound, named approval/data-rights/privacy/compatibility/funding records and positive funded allowance. Caps are ≤24cases,96dispatches,2,000,000reserved tokens,600seconds and$100 declared allowance. These are maximum kit bounds, not recommended spending. Use tighter owner-approved values.

Live dry run requires `--mode live --cases <exact IDs> --max-cases <n> --policy <private file> --dry-run`. It prints IDs/limits/model/missing opt-ins, never reads image pixels or constructs a live provider. Actual execution additionally requires `--execute-live`, explicit process fake=false/paid=true, reviewed-live policy=true, matching model and backend-only key. Missing prerequisites fail before construction/dispatch. App `.env.local` and public challenge availability are not changed. The private evaluation CLI calls the actual handlers under its own explicit budget; it does not enable or bypass visitor admission in the product.

Reserve the exact outgoing request's UTF-8 text bytes plus the separately reviewed model-specific image-token upper bound and8192output tokens before each attempt. Do not count base64 bytes as image tokens. Charge failed/refused/incomplete/unknown attempts without refund or retry; enforce serial work and an independent whole-run abort deadline, including an abort-ignoring transport. Retain unknown reservations. Stop further work if actual reported usage exceeds its reservation. Reports carry validated input/output/total counters when present; absent usage is unknown, never zero. The declared dollar allowance is an acknowledged external funding limit, **not an enforced vendor/account currency cap**. The funding reviewer must reconcile conservative token reservations with selected-model pricing and account controls before authorization. Process termination/scaling/restarts are not durable spend controls.

Reports contain fixed IDs, counts, safe codes, model/prompt/schema versions, dates, latency, usage, source hashes and actual image hashes. No provider prose, room/chat/photo payloads, filenames from visitors, key or encrypted reasoning is emitted. Exact-source lineage identifies this run; it is separate from RM-014 strict Linux release proof. New runs must not silently replace an old receipt.
