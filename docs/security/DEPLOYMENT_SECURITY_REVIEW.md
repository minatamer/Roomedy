### DEP85-01 — body-parser2.3.0: High upstream; inactive vulnerable code

The [maintainer advisory](https://github.com/expressjs/body-parser/security/advisories/GHSA-27r3-jxmh-p828) identifies a compressed-body trailing-data crash in versions below2.4.0 on the2.x line; patch2.4.0 is available. Local path is `apps/backend dependencies → express5.3.0 → body-parser2.3.0`. Express exposes parser factories; constructing Express does not mount them. **Roomedy never calls/mounts `express.json/raw/text/urlencoded` or body-parser middleware.** It uses its own finite `http/body.ts`, which rejects non-identity Content-Encoding before registering data handlers, and closes rejected HTTP connections.

Bounded offline proof replaces all four Express parser factories with fail-fast sentinels, constructs the real app, observes **zero parser calls**, and verifies gzip/deflate/br rejection before reading, with zero metered dispatch/network. Existing HTTP/body/bridge tests also pass in the current full gate. The advisory's necessary decompression path is absent. This supports an inactive-code disposition, not a claim that the package is patched.

**Plan if that boundary changes:** keep compressed requests unsupported; if a parser is deliberately introduced, select a compatible parent update or a narrowly tested2.4.0 resolution after checking its release notes, frozen-lockfile diff and body/admission/error regressions. Never mount a default inflating parser in front of current admission/bounds. Recheck compressed trailing-data rejection and later valid requests. Today an override creates dependency behavior churn without fixing an exposed path, so no upgrade is selected. Reassess during the next planned dependency refresh; do not suppress the advisory.
