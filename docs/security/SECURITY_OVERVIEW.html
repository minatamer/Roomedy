HighSEC-001 · Reproduced in the actual Linux image

Two unfinished uploads can make AI stay busy.

A client can start two requests, send only part of each upload and leave them unfinished. The screen receives a timeout, but the server keeps both request slots occupied. Later requests are refused—even after those first clients disconnect.

No verification token, account or paid call is needed. This blocks fresh photo and Medy admission on the affected process. The ordinary pages and manual editor remain available.

Recommended: repair before public deployment.

Make the upload deadline cancel and retire its own input stream. Preserve the separate protection that retains already-dispatched upstream work until it settles. Then repeat the exact two-upload test and release checks.

Evidence: real 15-second timeouts returned 408/408; later complete input returned 429, including after disconnect. No upstream or provider request.

MediumSEC-002 · Conditional on paid activation

A budget alert does not stop provider spending.

Roomedy already limits request rates, concurrent jobs, model rounds and output. Those controls reset with each process and do not set a spending limit over time or across overlapping revisions. Human verification helps with bots; it is not a money cap.

The budget alert is useful, but an enforceable provider funding boundary has not been verified. This is an unverified account condition, not an observed overspend.

Recommended: keep paid AI off for the first hosted checks.

Verify the actual provider funding cutoff and acceptable outstanding exposure before public paid activation. Use existing account controls where possible; do not add a new quota database just for this demo.

A paid-off release can be assessed separately. Domain and Turnstile hostname setup remain scheduled for later, as requested.
