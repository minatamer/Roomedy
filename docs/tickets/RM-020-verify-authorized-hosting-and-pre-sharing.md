3. Verify the exact candidate still matches local quality/security/visual evidence and Linux release proof. Material drift triggers affected local rebuild/review before publication. Never deploy a different dirty worktree merely because its commit subject resembles the approved ticket.

Record alerts versus enforced cutoffs honestly; restart/multi-instance assumptions remain explicit.
6. Run only approved bounded live corpus/walkthrough cases from RM-013, with finite dispatch/token/time/spend ceilings and safe owned test photos. Cover rough 2D draft/correction → main editor, meaningful assistant proposal/Apply/Undo, manual fallback and a controlled unavailable/busy outcome. Stop at any ceiling; no hidden retry.
7. Verify selected domain/TLS and redirects only when configured and authorized. `tryroomedy.com` is the chosen spelling, not proof of registration/control. Check asset/worker URLs, caching/no-store, response/security headers and safe failure copy on the actual hosted origin.
8. Complete a proportionate pre-sharing matrix: phone/tablet/laptop core task, transient-photo disclosure, two-hour recovery/expiry, reset/export/import exclusions, provider privacy information, no unsupported accuracy/fit/pricing claim and preserved security finding dispositions. 9. Verify rollback to the identified prior immutable revisions, or review a concrete rollback plan if an actual switch is outside authorization. Record observations and candidate identity, not broad availability promises from a short smoke test.
10. Reproduced defects return to their owning source ticket/module with scoped authorization, regression and refreshed relevant proof. Material new security findings return for explicit selection. Present what passed, what remains blocked and whether the named release scope is ready for sharing; publication is not inferred from tests alone.
